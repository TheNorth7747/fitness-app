# Fitday MVP PRD v1.0

## 1. 问题陈述

手机用户打开健身网站时，常需要先自行决定练什么、组数怎么排，训练中又难以快速记录。Fitday 将入口收敛为“今天练什么”，按循环计划推进，并用账号保存个人训练数据。

## 2. 成功标准

1. 360–430px 手机宽度下无横向溢出，核心按钮触控高度不小于 44px。
2. 用户可使用账号、密码、确认密码完成注册，并以同一账号重新登录。
3. 四套计划可选，腿臀日按股四头肌或臀大肌侧重生成。
4. 首页显示当前循环日、动作、总组数和预计时长；支持替换同组候选动作。
5. 用户可记录每个动作的组数、重量、次数并完成训练。
6. 训练完成后循环日前进一天，记录写入 PostgreSQL。
7. 刷新或重新登录后计划、偏好和历史保持存在。
8. 任一用户无法通过接口读取或修改其他用户数据。
9. 反例：只展示动作不能记录、刷新丢失、依赖浏览器本地数据库、手机端横向溢出，均不通过。

## 3. 范围

### 做

- 账号密码注册、登录、退出、30 天会话
- 首次选择场地、计划、腿臀侧重
- 四套循环计划与候选动作替换
- 今日训练、组次记录、组间倒计时、训练完成
- 根据动作历史预填重量，按双进阶规则给出可解释的下一次建议
- 训练草稿跨刷新/退出恢复，训练完成总结、PR 检测
- 动作趋势、最佳预估 1RM、训练记录详情、个人数据导出
- 1,324 条动作搜索、肌群/器械/目标筛选、中文名称、详情、中文步骤、同部位推荐
- 计划自定义：自选动作、调整各动作组数（1–8），展示推荐动作与组数作为参考，按训练日保存
- 计划自定义：自选动作、调整各动作组数（1–8），展示推荐动作与组数作为参考，按训练日保存
- 移动优先 PWA、离线缓存、安装到桌面、Docker Compose 部署

### 不做

AI 私教、饮食、社交、商城、体脂照片、穿戴设备、自由计划编辑器、复杂进阶算法、短信或微信登录。

## 4. 访问与账号流程

首次打开直接进入首页，不弹出登录页。游客可查看今日目标、动作库和默认计划；登录与注册只出现在「我的」。游客点击开始训练、更换动作或更换计划时，跳转到「我的」并提示登录。登录后若尚未选择计划，进入计划选择页；已有计划则回到首页，训练记录写入账号。

## 5. 计划规则

计划参考 B 站好人松松健身 Excel 套表，转换为四层结构：

`计划 → 循环训练日 → 动作组 → 候选动作`

动作组保存 `selectMin`、`selectMax`、`totalSets`，将原表“选 1–2 个动作，共 6–8 组”准确拆分，不把总组数错误复制到每个动作。

训练采用循环日，不绑定星期。完成训练后 `cycle_position` 前进一位。

## 6. 数据模型

- `users`：账号、scrypt 密码哈希、当前计划、腿部侧重、循环位置、动作替换 JSONB
- `sessions`：SHA-256 会话令牌哈希、过期时间
- `workouts`：用户、计划、训练日、开始与完成时间
- `workout_sets`：动作、组号、次数、重量

所有个人数据查询均带用户 ID 条件。计划与动作库为公共只读数据。

## 7. 视觉方向

采用 openGym 的深色训练应用气质，但使用 Fitday 自有布局与组件，不复制其代码或样式。

- 页面背景 `#090b08`，卡片 `#171b14`，线条 `#2b3126`
- 主文字 `#f2f5ec`，辅助文字 `#929a8b`，强调色 `#c8f45a`
- 大标题使用紧凑字距，数字优先使用等宽数字
- 卡片采用 16–24px 圆角，底部导航使用浮动圆角容器
- 动作库先展示肌群分类卡，再进入筛选和动作列表；详情用底部大卡片承载媒体、步骤和相关动作
- 动效仅用于进入、按压与休息倒计时
- 训练页采用低干扰单任务布局
