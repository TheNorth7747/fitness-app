# 部署到 Ubuntu 云服务器

这个项目是**纯静态站点**，迁移非常简单：把文件传上去 + 配一个 Nginx 指过去，**不需要 Node、数据库或任何后端进程**。

已实测确认（决定了下面每一步的配置）：

| 检查项 | 结果 | 影响 |
|---|---|---|
| `fetch` / `XHR` / `WebSocket` | **零调用** | 纯静态，无需后端 |
| `location.href` / `pushState` | **无** | 页面内栈式路由，**不需要 `try_files` 回退** |
| 资源引用 | 全为 `assets/...` 相对路径 | 可部署在子路径（如 `/fitness/`） |
| 站点体积 | 1.1 MB（gzip 后 **168 KB**） | 1核1G 机器绰绰有余 |
| 媒体来源 | jsDelivr CDN + 内置 SVG 降级 | 服务器**不需要**存图片 |
| 数据存储 | localStorage | 换域名/协议 = 用户数据重来（正常现象） |

## 零、最快路径：服务器上直接克隆后运行

仓库为**公开仓库**，服务器**不需要 SSH 密钥**，也**不需要 scp 上传脚本**。
SSH 登录服务器后执行：

```bash
cd ~
git clone https://github.com/TheNorth7747/fitness-app.git
cd fitness-app
sudo bash deploy-ubuntu.sh
```

脚本会自动完成：安装 Nginx → 同步部署文件 → 设置权限 →
写入含 gzip 优化的配置 → 启动服务 → 验证首页与数据文件。

> 脚本特意**只复制 `index.html` 和 `assets/`**，不会把 17MB 的 `data/` 下载到服务器。

> ⚠️ **必须用 root 或 sudo 运行**。脚本需要 `apt install` 并写入 `/etc/nginx/`，
> 普通用户（如 `admin`/`ubuntu`）直接跑会在中途失败——脚本开头会主动检查并提示。

> ❗ 报 `bash: /tmp/deploy-ubuntu.sh: No such file or directory`
> 说明脚本还没下载到服务器。**不要去 `/tmp` 找**，用上面的 `git clone` 才是正解。

### 出问题了？跑诊断脚本

`curl http://127.0.0.1` 连不上（port 80 无监听）时：

```bash
cd ~/fitness-app
sudo bash diagnose-nginx.sh
```

若 `~/fitness-app` 不存在，先 `git clone` 再跑。

它会逐项检查并自动修复：Nginx 是否安装、服务状态、端口占用/冲突
（apache2 抢占）、配置语法、站点软链接、文件是否部署，
最后验证首页、数据文件与 gzip 是否正常。

**常见根因**：

| 现象 | 根因 | 处理 |
|---|---|---|
| `bash: /tmp/xxx.sh: No such file` | 脚本未下载到服务器 | `git clone` 后在仓库目录内运行 |
| `curl: (7) Failed to connect ... port 80` | 脚本没用 root 跑，apt 静默失败 | `sudo bash deploy-ubuntu.sh` |
| 同上，但脚本已 root 跑过 | 配置没写入或服务未启动 | 跑 `diagnose-nginx.sh` |
| 同上，且 80 端口被 apache2 占用 | 两个服务抢端口 | 诊断脚本会自动停掉 apache2 |
| 容器/精简系统无 systemd | `systemctl` 不存在 | 脚本已兼容，会直接调 `nginx` 二进制 |

## 零点五、绑定域名 n0rth.asia + HTTPS

服务器公网 IP：**8.163.88.104**　域名：**n0rth.asia**

### 第 1 步：添加 DNS 记录（阿里云控制台）

域名已托管到阿里云 DNS（NS: dns1.hichina.com），但**尚未配置 A 记录**，需先添加：

| 记录类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | `8.163.88.104` | 默认 600 |
| A | `www` | `8.163.88.104` | 默认 600 |

添加后验证解析（本地可能受 DNS 污染，以服务器上查询为准）：

```bash
dig +short n0rth.asia          # 应返回 8.163.88.104
```

### 第 2 步：运行配置脚本

DNS 生效后（约 10 分钟）在服务器执行：

```bash
cd ~/fitness-app
git pull                    # 拉取含 setup-domain.sh 的最新版
sudo bash setup-domain.sh
```

脚本自动完成：DNS 校验 → 写 Nginx 域名配置（含 gzip）→ 装 certbot →
申请 Let's Encrypt 证书（含 www，自动续期）→ 验证。

### 第 3 步：安全组放行 443

阿里云控制台 → 安全组 → 添加规则：

| 端口 | 协议 | 源 |
|---|---|---|
| 443 | HTTPS | 0.0.0.0/0 |
| 80 | HTTP | 0.0.0.0/0 |

> 80 端口保留是为了 certbot 的 HTTP-01 验证和 HTTP→HTTPS 跳转。

### 验证清单

```bash
curl -I https://n0rth.asia                    # 期望 200
curl -sI https://n0rth.asia | grep -i strict  # 期望 HSTS 头
certbot certificates                          # 查看证书有效期
systemctl list-timers | grep certbot          # 确认自动续期
```

> ⚠️ 绑定域名后**裸 IP 会失效**（server_name 匹配不到）。
> 建议先确认域名访问正常，再考虑是否加一个 default_server 兜底。

## 一、准备工作

### 0. 仓库可见性决定认证方式

| 仓库类型 | 克隆地址 | 是否需要密钥 |
|---|---|---|
| **Public** | `https://github.com/TheNorth7747/fitness-app.git` | **不需要** |
| Private（SSH） | `git@github.com:TheNorth7747/fitness-app.git` | 服务器需配置 SSH 密钥 |
| Private（HTTPS） | `https://github.com/TheNorth7747/fitness-app.git` | 需 Personal Access Token |

如果服务器报 `Permission denied (publickey)`，说明用了 SSH 地址但服务器没密钥。
**公开仓库直接换成 HTTPS 地址即可**，无需任何配置。

**要传**（1.1 MB）：

```

assets/
```

**不用传**（本地开发用，17 MB 的大文件不必上云）：

| 目录 | 体积 | 说明 |
|---|---|---|
| `data/` | 17 MB | 原始开源数据集，改数据时才需要 |
| `tools/` | 52 KB | 构建脚本 |
| `docs/` | 692 KB | 文档与截图 |

> `data/` 和 `tools/` 只在你要**重新生成动作数据**时才用到（见文末「更新数据」）。

### 2. 传文件的三种方式

**方式 A：scp（最直接）**

在 **Windows 本地**执行：

```bash

scp -r index.html assets user@your-server-ip:/tmp/fitness-upload/
```

**方式 B：先打包再传（推荐，文件更少更干净）**


**方式 C：Git 部署（适合需要频繁更新的场景）**


>
> 仓库地址：https://github.com/new?name=fitness-app

> 完整自动化流程见项目根目录的 `setup-github.bat`（双击运行即可）。

> ⚠️ **服务器报 `Permission denied (publickey)` 时**：

## 二、服务器端配置

SSH 登录后：

```bash
sudo apt update
sudo apt install -y nginx
```

### 1. 放置文件

```bash
sudo mkdir -p /var/www/fitness
sudo tar -xzf /tmp/fitness.tar.gz -C /var/www/fitness
# 或从 scp 的目录复制
# sudo cp -r /tmp/fitness-upload/* /var/www/fitness/

sudo chown -R www-data:www-data /var/www/fitness
ls -la /var/www/fitness          # 确认 index.html 和 assets/ 都在
```

### 2. Nginx 配置

```bash
sudo nano /etc/nginx/sites-available/fitness
```

写入（**注意已按本项目实测优化**）：

```nginx
server {
    listen 80;
    server_name your-domain.com www.your-domain.com;

    root /var/www/fitness;
    index index.html;

    # ---- 关键 1：gzip ----
    # 919KB 的动作数据文件压缩后仅 130KB，首屏传输量从 1.1MB 降到 168KB
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript
               application/json image/svg+xml;
    gzip_comp_level 6;

    # ---- 关键 2：静态资源缓存 ----
    # 带 hash 语义的资源可长期缓存；HTML 不缓存，保证更新能立即生效
    location ~* \.(js|css|svg|png|jpg|gif|ico|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
        access_log off;
    }

    location / {
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ =404;
    }

    # ---- 关键 3：安全响应头 ----
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    client_max_body_size 1m;      # 本项目纯 GET，留最小值即可
}
```

> **关于 `try_files $uri $uri/ =404`**：本项目用的是页面内栈式路由（URL 不变），所以**不要**配 SPA 的 `try_files $uri /index.html`——那是不必要的。配 `=404` 反而能帮你发现路径写错的问题。

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/fitness /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default    # 避免和默认站点抢 80 端口
sudo nginx -t                                  # 语法检查
sudo systemctl reload nginx
```

### 3. 开放防火墙

```bash
sudo ufw allow 'Nginx Full'     # 如果用 ufw
# 云服务商控制台的安全组也要放行 80 / 443
```

### 4. 配置 HTTPS（强烈建议）

小程序场景下 HTTP 会有诸多限制，且属于敏感的健康数据。

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com -d www.your-domain.com
```

Certbot 会自动改写 Nginx 配置并设置 HTTP 跳转 HTTPS。完成后验证：

```bash
curl -I https://your-domain.com
```

## 四、国内服务器优化（可选但重要）

如果你的服务器在国内，用户访问 jsDelivr 可能很慢甚至超时。图片加载失败时会自动降级成灰色「暂无图」占位块，**不影响任何功能**，但观感差。

三种应对方案：

### 方案 1：换国内 CDN（改动最小，推荐先试这个）

改 `tools/build_data.py` 里的 CDN 常量：

```python
CDN = "https://cdn.jsdelivr.net/gh/hasaneyldrm/exercises-dataset@main/"
# 换成任一可用镜像，例如：
# CDN = "https://fastly.jsdelivr.net/gh/hasaneyldrm/exercises-dataset@main/"
# CDN = "https://gcore.jsdelivr.net/gh/hasaneyldrm/exercises-dataset@main/"
```

然后重新生成：

```bash
python tools/build_data.py
```

重新打包上传即可。

### 方案 2：把图片镜像到自己的对象存储

如果图片加载要求高，可以把 1,324 个动作图 + GIF 镜像到阿里云 OSS / 腾讯云 COS，然后改 CDN 指向。同样改 `build_data.py` 里的 `CDN` 常量。

### 方案 3：服务器反代（不推荐用于大并发）

Nginx 反代 jsDelivr 会把流量压到自己机器上，图片 1,324 × GIF 单个 90 KB，**不适合**。除非服务器带宽很闲，否则不建议。

## 五、数据与更新

### 用户数据存在哪

Demo 的训练记录、身体数据存在**浏览器 localStorage**，键名 `fitness_mvp_v1`。

这意味着：

- 用户数据**只在他自己的浏览器里**，换设备/换域名/清缓存都会丢失
- 这对演示足够，但真实产品需要接后端（见设计文档 v1.1 计划）

「我的 → 重置演示数据」可恢复初始状态。

### 更新动作数据后重新部署

如果修改了 `tools/build_data.py`：

```bash
# 本地（需要 data/exercises.json 原始数据）
python tools/build_data.py
python tools/build_plans.py

# 重新打包上传
tar -czf fitness.tar.gz index.html assets
scp fitness.tar.gz user@your-server-ip:/tmp/
# 服务器上
sudo tar -xzf /tmp/fitness.tar.gz -C /var/www/fitness
```

> 重新生成后 `exercises-data.js` 的内容会变，但**文件名没变**。Nginx 配了 30 天缓存，
> 所以老用户可能拿到旧数据。开发期建议把缓存临时改成 `expires 1h`，
> 或给文件名加版本号。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| `bash: /tmp/xxx.sh: No such file or directory` | 脚本没上传到服务器。公开仓库无需 scp，`git clone` 后在仓库目录内运行 |
| `fatal: not a git repository` | **在错误的目录下执行了命令**。看提示符是否为项目路径，先 `cd C:/Users/Administrator/Desktop/Fitness_APP` 再执行 |
| 服务器 `Permission denied (publickey)` | 服务器无 GitHub SSH 密钥。**公开仓库改用 HTTPS**：`git clone https://github.com/TheNorth7747/fitness-app.git` |
| `Repository not found` | **GitHub 上还没建这个仓库**。先访问 https://github.com/new?name=fitness-app 创建空仓库（不要勾选 README/.gitignore），再 `git push -u origin master` |
| `Permission denied (publickey)` | SSH 公钥未添加到 GitHub。把 `~/.ssh/id_rsa.pub` 内容粘贴到 https://github.com/settings/ssh/new |
| `Host key verification failed` | 未登记 GitHub 主机密钥。执行 `ssh-keyscan -t rsa,ecdsa,ed25519 github.com >> ~/.ssh/known_hosts` |
| `remote origin already exists` | origin 已配置。用 `git remote set-url origin <新地址>` 改地址，而不是 `add` |
| `nothing added to commit` | 该提交已存在，不是错误。用 `git log --oneline` 确认历史 |
| `Updates were rejected` | 远程有本地没有的提交。要么先 `git pull --rebase origin master`，要么（确认无误后）`git push --force` |
| 打开是 403/404 | 文件没放对位置。确认 `/var/www/fitness/index.html` 存在，且 Nginx `root` 指向该目录 |
| 样式全乱、脚本不执行 | Nginx 没把 `.js`/`.css` 正确返回。检查是否误配了 `add_header` 导致 Content-Type 错误 |
| 动作数据加载报错 | 请求 `/assets/js/data/exercises-data.js` 返回 404。确认 `assets` 目录递归上传完整 |
| 图片全是灰色占位块 | jsDelivr 不可达。见「国内优化」 |
| 用户数据每次打开都重置 | 域名/协议变了导致 localStorage 隔离，属预期行为 |
| 502 Bad Gateway | 没配 `try_files $uri $uri/ =404`，或 root 路径错 |
| 想放到子路径如 `/fitness/` | 资源全是相对路径，直接把 `/var/www/fitness` 软链到对应 location 即可，**无需改代码** |
