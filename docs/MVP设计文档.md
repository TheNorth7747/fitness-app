# 健身助手 · MVP 产品设计文档

> 微信小程序形态的健身训练应用原型 · v1.0

---

## 一、产品定位

### 1.1 一句话定义

一个**面向健身新手的训练执行工具**：告诉用户「今天练什么、怎么练、练到什么程度」，并把每一次训练沉淀成看得见的进步。

### 1.2 目标用户

| 优先级 | 画像 | 核心诉求 | 对应功能 |
|---|---|---|---|
| P0 | 健身新手（0-6 个月） | 不知道练什么、动作不标准 | 训练计划 + 动作库 |
| P1 | 有基础的进阶者 | 需要分化方案、突破平台 | 五分化 / PPL + 数据统计 |
| P2 | 居家/出差人群 | 没器材、没时间 | 居家哑铃 / HIIT 计划 |

### 1.3 解决的核心问题

传统健身 App 的两大痛点：

1. **信息过载** —— 1324 个动作、新手不知道从哪挑起
2. **执行断层** —— 计划是静态的文档，训练完没有反馈，下次不想再打开

本产品的解法：**把「计划」和「动作库」打通，再把执行结果回流成数据。**
用户在训练日点开就能看到当天全部动作（含 GIF 演示和中文要领），打勾完成，
数据自动进入「我的」页的身体趋势与执行统计。

## 三、四大模块设计

### 3.1 首页 —— 回答「今天练什么」

用户打开 App 的第一屏，必须在 3 秒内回答：**今天练什么、练到哪一步了。**

| 元素 | 说明 |
|---|---|
| **今日训练目标卡** | 绿色渐变主卡。环形进度显示完成度，中央显示「已练组数/总组数」；右侧显示训练日名称与部位重点 |
| **预计时长 / 动作数 / 总组数** | 三个 chip 给出训练量的直观预期 |
| **开始训练按钮** | 主 CTA，跳转到训练执行页 |
| **当前计划条** | 显示正在执行的计划，点击可切换 |
| **四个数据格** | 本周训练次数、连续打卡、累计容量、累计时长 |
| **本周日程** | 周一到周日 7 格，今天高亮、已练打勾 |
| **今日动作清单** | 今日全部动作缩略图 + 组数/次数/休息时间，已完成的置灰划线 |
| **快捷入口** | 动作库 / 选计划 / 我的数据 |

**设计要点**：首页不做任何"今日推荐动作"的随机内容，只呈现**当前计划的确定性安排**。
健身需要的是可预期，而不是惊喜。

### 3.2 动作库 —— 回答"这个动作怎么做"

数据源：[hasaneyldrm/exercises-dataset](https://github.com/hasaneyldrm/exercises-dataset)（MIT，1,324 个动作）

| 能力 | 实现 |
|---|---|
| 搜索 | 支持中文名（杠铃卧推）、英文名（bench press）、目标肌群 |
| 三维筛选 | 训练部位（10 类）／所需器械（13 类）／目标肌群（19 类），可组合 |
| 动作卡片 | 180×180 缩略图 + 中文名 + 目标肌群 + 器械标签，3 列瀑布 |
| 动作详情 | GIF 动画演示 + 部位/器械/目标标签 + 主要与协同肌群 + 4~6 步中文要领 |
| 收藏 | 详情页收藏，收藏项在列表中自动置顶 |
| 规模 | 全量 1,324 条，滚动分页加载 |

**中文本地化**：数据集提供 10 种语言的步骤说明，中文覆盖 100%（1,324/1,324）。
动作名称为英文，项目内建了「多词短语优先 + 单词兜底 + 退化回退」的三段式译名管线，
1,321 条（99.8%）已译为中文，仅 3 条极冷门体操动作回退为「目标肌群 + 训练动作」。

### 3.3 训练计划 —— 回答"我该怎么练"

内置 6 套方案，按难度分组：

| 分组 | 计划 | 频率 | 适合 |
|---|---|---|---|
| **入门友好** | 新手三分化 | 3 天/周 | 初次进健身房 |
| | 居家哑铃 · 全身循环 | 4 天/周 | 家里只有哑铃 |
| | 燃脂 HIIT · 无器械 | 3 天/周 | 20 分钟、零器械 |
| **进阶推荐** | 三分化 · 推拉腿（PPL） | 6 天/周 | 已练 3 个月以上 |
| | 四分化 · 上下肢 | 4 天/周 | 追求均衡 |
| **高阶专项** | 五分化 · 胸背肩腿臂 | 5 天/周 | 训练 1 年以上 |

每个计划包含：难度、目标、适不适合你的三条描述、计划特点标签，
以及**每个训练日的完整动作编排**（组数 × 次数 × 组间休息）。

切换计划后，计划开始日重置为当天，主页的「今天练什么」立即按新计划重新分配。

### 3.4 我的 —— 回答"我有什么变化"

| 分区 | 内容 |
|---|---|
| **个人头部** | 昵称、性别、年龄、训练目标 |
| **身体数据** | 体重 / 身高 / 体脂率 / BMI（四宫格），可编辑 |
| **身体趋势** | 体重、体脂率折线图 + 变化量（近 9 次记录） |
| **计划执行情况** | 当前计划、本周完成率、本周 7 天完成状态条、图例 |
| **训练数据** | 累计训练次数 / 累计容量(吨) / 累计时长(时) / 连续打卡(天) |
| **近 4 周频率** | 柱状图，看训练是否规律 |
| **部位分布** | 各部位累计训练次数，识别训练短板 |
| **训练历史** | 按时间倒序的每条记录（日期、训练日、组数、时长、容量） |

**设计要点**：执行统计和身体数据放在一起，而不是分两个页面。
用户要回答的核心问题是"我的付出有回报吗"，这两个信息必须并置。

## 四、核心数据模型

```js
// 全局状态（localStorage 持久化，key: fitness_mvp_v1）
{
  profile: {                    // 身体基本信息
    name, age, height,          // cm
    weight,                     // kg
    bodyFat,                    // %
    gender, goal, updatedAt
  },
  bodyHistory: [                // 身体数据变化趋势
    { date, weight, bodyFat }
  ],
  currentPlanId,                // 当前执行的计划
  planStartDate,                // 计划开始日 → 决定「今天是第几个训练日」
  planProgress: {               // 计划执行进度
    "ppl#0": { doneSets, totalSets, done, sets_: {动作索引: 已完成组数} }
  },
  records: [                    // 训练记录
    { date, planId, dayIndex, dayName, focus,
      sets, volume, minutes, parts[] }
  ],
  favorites: [],                // 收藏的动作 id
  lastFilter: { q, bp, eq, t }  // 动作库筛选记忆
}
```

**关键设计：如何确定「今天是计划的第几天」**

```
diff     = 今天 - planStartDate
cycle    = floor(diff / plan.daysPerWeek)   // 第几个训练周
restDay  = diff - cycle * plan.daysPerWeek   // 该周内的第几天
若 restDay >= plan.days.length → 今天休息
否则 → 今天训练 plan.days[restDay]
```

这样切计划、重置进度、跨周循环都不需要额外的排期表。

## 五、技术实现

### 5.1 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 形态 | 纯 HTML/CSS/JS | 零依赖、免安装、双击即看，便于需求评审 |
| 框架 | 无（原生 JS + IIFE 模块） | 模拟小程序 Page/生命周期，代码结构可直接平移到真机 |
| 状态 | 自研 Store 单例 | 约 300 行，含 localStorage 持久化与统计计算 |
| 数据 | 构建期生成 JS 文件 | `window.EXERCISES` / `window.PLANS`，919 KB，避免运行时 fetch 跨域 |
| 媒体 | jsDelivr CDN | 1324 个 JPG + GIF 不落本地，按需加载，带 SVG 降级 |

### 5.4 动作数据管线

原始 `exercises.json` 有 17 MB、10 种语言，直接用不现实。
`build_data.py` 做四件事：

1. **枚举汉化** —— 部位 10 类、器械 13 类、目标肌群 19 类、肌肉 28 类
2. **译名生成** —— 三段式避免中文被二次吞掉：
   - 抽出括号补充与版本号（`v. 2` → `· 变式`）
   - 多词短语优先匹配，命中后写入 `\x00i\x00` 占位符**保护起来**
   - 剩余英文逐词查表（516 词表），占位符原样还原
   - 结果退化（只剩裸器械词）时按目标肌群回退
3. **说明清洗** —— 只保留中文分步，限制 6 条
4. **体积控制** —— 只留必要字段，中文名去重后 1,158 个

> 踩过的坑：短语替换产出的中文会被后续逐词查表当成"未翻译"而丢弃。
> 必须用占位符保护，这是三段式设计的核心。

计划数据 `build_plans.py` 把每个编排动作的英文名回查数据集取真实 id，
保证点进任意动作都能看到真实图片、GIF 和中文步骤（0 条未匹配）。

## 六、已实现 vs 待实现

### 6.1 MVP 已实现 ✅

- 四模块完整可交互，页面栈路由与小程序一致
- 1,324 个动作全量可搜索筛选，GIF 演示 + 中文要领 + 收藏
- 6 套训练计划，88 个编排动作全部关联真实数据
- 训练执行：按组打卡、进度条、完成写入记录、撤销
- 身体数据可编辑，BMI/体脂自动评价，体重体脂趋势图
- 执行统计：周完成率、连续打卡、累计数据、4 周柱状、部位分布、训练历史
- localStorage 持久化 + 一键重置演示数据

### 6.2 下一版建议（v1.1）

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 训练中计时器 | 组间休息倒计时 + 语音提示，这是留存的关键 |
| P0 | 云端同步 | 换设备数据不丢，接入微信登录 |
| P1 | 渐进超负荷建议 | 根据历史表现推荐下次加重/加组 |
| P1 | 计划自定义 | 用户自建计划，从动作库拖拽编排 |
| P2 | 训练容量曲线 | 参照 logpress 的统计视图，做长期趋势 |
| P2 | 分享卡片 | 生成训练战绩海报，可分享到朋友圈 |

### 6.3 明确不做（MVP 边界）

- 社交/排行榜/评论
- AI 教练与自动打分
- 饮食热量摄入记录
- 视频上传（识别动作）

理由：MVP 要验证的是「计划 → 执行 → 数据回流」这条主链路是否成立，
社交和 AI 都是在主链路跑通之后的加法。
